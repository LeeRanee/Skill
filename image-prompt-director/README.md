# 生图提示词导演

`image-prompt-director` 是一个面向 AI 图片创作的技能，帮助你梳理视觉需求、编写提示词、选择生图方式，并在确认后生成或编辑图片。它也可以把选中的结果整理成独立的可复用技能，用于制作同系列图片。

## 适用场景

- 为海报、产品图、插画等任务设计或优化生图提示词。
- 按指定模型的特点编写提示词，或使用可直接复制的通用写法。
- 使用参考图进行编辑、风格转换或多图合成，前提是所选工具支持相应输入。
- 在同一会话中迭代图片，保持角色特征、风格、配色等已确认设定。
- 将选中的图片结果整理为可替换变量的独立技能，并逐张确认生成系列图片。

仅需提示词时，说明“只写提示词”，技能会交付文本，不自动调用生图工具。纯图片搜索、图片内容识别和非生成式文件处理不属于本技能的主要用途。

## 如何使用

在支持技能发现的环境中安装或加载本目录；具体安装位置和启用方式以所用助手的规范为准。环境支持自动调用时，直接描述你的 AI 生图或图片编辑需求即可；也可以显式指定 `image-prompt-director`。Codex 环境可使用 `$image-prompt-director`。

例如：

> 帮我设计一张咖啡品牌海报，暖色调、竖版、画面无文字。先给我三个通用提示词方案，只写提示词。

> 参考我上传的产品图，保留包装形状和颜色，把背景改成简洁的暖色摄影棚。先展示修改方案。

> 把这张我选中的图片整理成可复用技能，以后只替换产品名称和场景，逐张生成同系列图片。

## Codex 首次创作的适配

在 Codex 中开始新的图片创作或编辑时，技能会检查并尝试登记随技能附带的 Hook；仅询问问题、只写提示词或修改本技能时不会执行此配置。其他 Agent 不执行 Codex 配置。

首次登记成功后，技能会停在设置说明，本轮不会生图。请在 Codex 中审阅并信任新 Hook（CLI 可使用 `/hooks`），然后重新提交创作请求，显式写入 `$image-prompt-director`。如果当前会话尚未加载新配置，再重新打开会话；新会话无法访问原参考图时，请重新附上必要图片。登记本身不等于信任，也无法追溯处理登记前已提交的消息。

如果已登记但当前轮没有收到 Hook 注入的生效标记，技能会提示检查信任状态，并显式输入技能名称后重试；不会把登记当作已生效。后续选择或确认同一创作方案时，不必反复输入技能名称。如果安装失败、权限不足或配置不受支持，技能会说明实际状态并停止，等待问题解决，不会声称安装成功。

Hook 不会修改输入框中的原文，只向模型追加上下文；其行为无法保证覆盖更高优先级的运行时规则。显式输入技能名称是匹配条件，点选技能能否产生相同标记取决于 Codex 实际提交的内容。脚本不会保存提示词或参考图。项目目录与 Magpie Library 中的已安装版本可能是独立副本；更新项目后，需要通过 Magpie 支持的方式更新已安装版本。

### 检查、修复与卸载

在实际加载的 skill 目录中，可运行 `python scripts/codex_hook_setup.py status` 检查登记状态。输出的 `trust: unknown` 表示脚本无法判断是否已信任；实际是否触发还需看创作请求所在轮的 Hook 反馈。命令默认使用 `CODEX_HOME`，未设置时使用用户目录下的 `.codex`；需要指定其他 Codex 配置目录时，在命令后加 `--codex-home <目录>`。

移动 skill 目录或 Python 解释器后，旧的 Hook 命令可能失效。若状态为 `stale_registration`，先审阅输出中 `config_path` 指向的 `hooks.json`，找到本技能旧的 `codex_prompt_hook.py` 命令；执行 `python scripts/codex_hook_setup.py uninstall --command <完整旧命令>`，将完整命令作为一个参数传入，再执行 `python scripts/codex_hook_setup.py install` 并重新审阅、信任。保留其他 Hook；不要自行猜测或删除不属于本技能的命令。

卸载当前路径登记时，运行 `python scripts/codex_hook_setup.py uninstall`；这不会删除 skill 文件或其他 Hook。配置异常、存在多个相同条目或权限不足时，脚本会报告状态，不应声称操作成功。

安装脚本异常中断时，Codex 配置目录可能遗留 `.image-prompt-director-hook.lock` 目录。确认没有安装或卸载进程正在运行后，才可删除该目录并重试。脚本会检查配置是否被其他程序更改，但与不使用同一锁的程序并发修改 `hooks.json` 时仍存在短暂竞态；请避免同时修改。Windows 上原 `hooks.json` 的自定义 ACL 无法保证在替换文件后保留。

## 工作流程

1. **理解需求**：明确主体、用途、风格、比例及文字要求。缺少关键信息时再询问。
2. **选择提示词写法**：可选择全模型通用写法，或指定具体模型；不必知道模型也能获得完整的通用提示词。
3. **查看视觉方案**：新创作默认提供三个不同方向，用户指定数量时按要求调整。英文提示词会附中文说明。
4. **选择生图方式并确认**：可选择 magpie-image MCP 或环境支持的原生生图方式，实际可用性取决于当前环境。生成前展示提示词、工具、模式和设置，取得对当前单张图片的明确确认。
5. **生成与检查**：按确认内容生成一张，展示真实结果并检查可见偏差。修改、重试或批量任务的下一张都需要重新确认。

技能默认推荐 magpie-image，但不会自动选择或静默切换工具。没有可用生图工具时，仍可使用提示词交付功能。图片生成可能消耗所选服务的额度；具体情况以服务实际规则为准。

## 交互方式

需要你决定时，优先使用当前环境支持的交互控件，按控件允许的问题数和选项数安排提问。模型选择会提供少量与任务相关的选项，其他模型可通过自由输入或文字补充。

在卡片上点选“确认生成”，或用文字明确确认已展示的当前方案，都可以授权该次单张生成，不会重复确认。控件不可用或不支持当前提问时，技能会说明原因并使用中文文字提问；批量任务仍需逐张确认。

## 参考图与会话一致性

同一会话中，技能会记录已确认的主体、风格、配色、构图等关键设定，并区分最初上传的参考图、其他参考图和选中的生成版本。生成新图不会自动替换原始参考图；你可以指定后续修改使用哪一张，或取消某张参考图。

只有明确要求基于图片编辑、转换或合成，并且图片可访问、工具支持传图时，才按图片编辑模式执行。图片不可访问或工具能力不足时，需要重新提供素材、选择支持的方式，或明确接受纯文本重建；文字描述不能保证精确复现原图细节。

技能优先使用当前会话中与任务相关的信息；需要会话外资料时，只按需读取指定内容。原始参考图默认不复制。若将结果沉淀为独立技能，且该技能确实需要参考图输入，必要素材会按其独立运行要求处理。

## 图片保存与命名

在工具和当前环境允许保存本地图片时，优先使用你指定的位置和名称。未指定时，默认放在当前工作区：

```text
outputs/生图/YYYY-MM-DD_主题/主题_序号_v版本号.实际扩展名
```

例如：

```text
outputs/生图/2026-10-27_咖啡海报/咖啡海报_01_v01.png
outputs/生图/2026-10-27_咖啡海报/咖啡海报_01_v02.png
outputs/生图/2026-10-27_咖啡海报/咖啡海报_02_v01.png
```

序号区分不同图片，版本号区分同一图片的续改。文件名会处理系统不允许的字符，扩展名与实际格式一致；同名冲突时递增编号，避免覆盖。工具无法导出或保存位置不可控时，以工具真实返回的结果和可用位置为准，不保证生成上述文件。

## 项目结构

```text
image-prompt-director/
├── SKILL.md                       # 技能主流程与内置提示词指南
├── README.md                      # 使用说明、交互方式与项目结构
├── agents/
│   └── openai.yaml                # Codex 等兼容环境的展示与调用元数据
├── scripts/
│   ├── codex_hook_setup.py        # 检查、登记或卸载 Codex Hook
│   └── codex_prompt_hook.py       # Codex 提示词上下文适配
└── references/
    └── result-to-skill.md         # 结果沉淀、独立技能和逐张批量复用规则
```

模型指南内置于 `SKILL.md`，无需每次联网读取；需要最新规则或未覆盖的专属语法时，再查询对应资料。生图工具能力、参数和图片编辑支持仍以实际环境为准。
