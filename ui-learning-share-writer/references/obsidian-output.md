# Obsidian 落盘规范

仅在需要保存最终学习分享时使用。正文仍须遵守 SKILL.md 的材料边界、提纲确认与格式要求。

## 路径与命名

- 保存目录：vault 根目录下的 `04_工作学习/泛联/学习分享/`。
- 文件名：`关于《原文标题》的学习分享.md`。
- 主题写作以用户明确指定的主题作为命名内容，不虚构文章来源。
- 尚未知道 vault 根目录时先询问，不能把当前工作目录默认当作 vault。
- 写入前核实被点名原文的实际位置，仅在已授权范围内定位该材料，不浏览或读取其他文章。找不到确切路径时停下来询问，不写猜测路径。
- 文件名受文件系统限制或目标文件已存在且未获得覆盖授权时，先解决具体命名或覆盖问题，不擅自改题或覆盖。

## Frontmatter

只保留 `title`、`created`、`sources` 三项。禁止添加 `tag`、`tags`、`keywords`、`categories`、`aliases`、`topics` 或其他字段。

- `title`：与文章题名一致，通常为“关于《原文标题》的学习分享”。
- `created`：采用用户所在时区的实际创建日期，格式为 `YYYY-MM-DD`，不虚构日期。
- `sources`：YAML 列表，每项只能是双引号包围的 Obsidian 双链。

结构示意，写入时必须替换示意值：

```yaml
---
title: "关于《原文标题》的学习分享"
created: "YYYY-MM-DD"
sources:
  - "[[完整相对路径/原文文件名|原文标题]]"
---
```

### sources 的精确规则

- 路径从 vault 根目录起算，不带开头的 `/`，不带 `.md`，使用 `/` 分隔目录。
- 路径必须对应实际存在且由用户点名的文件，不能由文章标题推测。
- 竖线后是阅读视图显示的原文标题，不带路径或扩展名；竖线两侧不留空格。
- 中文括号、引号和书名号原样保留，不转义。YAML 字符串中确有 ASCII 双引号或反斜杠时，按 YAML 语法处理，不改变实际标题与路径。
- 不混写纯文本路径、URL、单独文件名或说明性文字。
- 原文标题自身含 `|` 时，省略显示标题，写成 `- "[[完整相对路径/原文文件名]]"`，并在正文外的交付说明中注明。
- 有多个明确指定来源时，每个来源各占一个列表项，逐一核实，不追加相关但未指定的笔记。
- 来源是粘贴正文、附件或网页，且没有已确认的 vault 原文路径时，先询问其对应的实际笔记路径；不能用 URL 代替，也不能伪造路径。
- 纯主题写作确无原文文件时，可以使用 `sources: []`。已知有来源但路径未确认时，不能用空列表掩盖缺失，应先询问。

## 正文与井号

Frontmatter 后直接写 1-6 段连续正文，不额外添加 Markdown 标题。Frontmatter 的来源双链不属于正文。

- 若在允许标题的位置书写 Markdown 标题，井号后必须有空格，例如 `# 标题`；此规则不表示要给正文添加标题。
- 正文非标题位置的 `#` 用行内代码包裹，例如 `` `#` ``。
- 禁止直接书写 `#标签`。已有代码块内的 `#` 无需转义；不为此额外添加代码块。

## 写入前后检查

1. 提纲分支已获得明确开写授权，正文已通过六维终审。
2. 保存位置、文章题名与所有来源实际路径已核实，写入或覆盖已在授权范围内。
3. Frontmatter 恰好只有三个允许字段，YAML 有效，sources 每项符合双链格式。
4. 正文无标题、列表、编号、链接或裸路径，井号已正确处理。
5. 写入后回读核对内容、编码、路径和来源。交付时在正文外说明保存位置及标题含 `|` 等必要例外。
