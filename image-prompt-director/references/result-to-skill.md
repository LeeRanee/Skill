# 结果沉淀与批量复用

仅在用户要求保存、复用或制作批量模板时进入本流程；普通生图结束后不自动建文件。沉淀只整理已有结果，不通过重新生图补齐记录，也不把保存授权当作生图授权。

## 1. 确定来源与配方

从用户选中的结果和可访问记录中按需收集材料，不遍历无关资料；明确选中了哪张时不重复询问。有多个候选且未指明时，用一张卡片列出候选（每项写清序号、缩略描述和来源），用户点选即可，不擅自混合不同结果。区分最初上传的参考图和选中的生成版本，记录各自的真实可访问位置或标识及用途；仅根据实际记录说明其关系，不假称未传入的图片参与生成。

- 保存实际最终提交的提示词及已知生成设置；区分用户原始提示词、工具可见改写与不可见的服务端处理，不把草案当最终输入。
- 检查可访问的选中图片，提取构图、光线、配色、材质、风格、文字策略等可复用特征。分别标明“来自实际记录”和“根据图像观察归纳”；不从图片推断模型、种子、采样或隐藏参数。
- 若只有图片、缺少原始提示词，说明将根据可见图像重建配方，展示重建内容供用户确认；不能称为恢复原始提示词，也不承诺精确复现原图。图像和记录都无法访问时，请用户补充所需材料，停止提取。
- 将核心视觉特征作为固定项；只把用户计划批量替换的主体、文案、场景等设为变量。列出变量名、含义、必填与否及有依据的默认值，不将所有风格细节都变量化。
- 保存已选的通用或模型专用写法；只记录真实已知的模型信息。不携带凭据、临时下载地址或不相关对话。

## 2. 保存预览与目录

写入前展示：skill 名称与用途、来源及记录缺口、固定项、变量与默认值、完整提示词模板、已知设置、必要参考图用途、目标目录和文件清单。名称用小写字母、数字、连字符，少于 64 字符，文件夹与名称一致。

尊重用户指定位置；未指定时按目标 Agent 的技能目录约定保存。在 Codex 中使用 `$CODEX_HOME/skills/<name>`，`CODEX_HOME` 未设置时使用 `~/.codex/skills/<name>`；其他 Agent 的目录约定无法从环境确认时，按交互协议询问保存位置，把已确认的默认目录作为推荐项，不默认安装到 Codex 目录。预览展示完毕后请求明确写入授权（“确认写入（推荐）”“先调整内容”“换个目录”），可通过卡片或文字确认；控件不可用时按交互协议回退。目录已存在时检查其用途，不覆盖无关 skill；需要更新既有 skill 时先展示差异及文件范围。按当前环境要求取得文件写入审批，已有明确授权覆盖该预览范围时不重复索要。预览变更超出授权范围时先补充确认。

生成的 skill 必须自包含：将实际配方及必要运行规则写入新目录，不要求加载 image-prompt-director、skill-creator 或原对话。无需复制导演技能的完整模型指南，只保留当前配方需要的写法和工具适配限制。

最小必需产物为 `SKILL.md`；`agents/openai.yaml` 仅在面向 Codex 时按需生成，不是跨 Agent 使用的前提。提示词、变量、确认流程和工具发现规则必须保存在 `SKILL.md` 或其明确引用的随附文件中，不能依赖该 YAML 才生效。只有确需输入图片时增加 `assets/`。内容较长时可使用新 skill 内部的相对引用拆分参考文件，但所有引用必须在交付目录内可用。不添加空目录、通用脚手架或无具体用途的脚本。

### 独立 skill 的内容要求

以下是生成内容的检查项，不是留给用户填写的空白模板；输出时替换为本次实际配方：

| 内容 | 必须落地的信息 |
| --- | --- |
| Frontmatter | `name` 与准确的 `description`，说明生成何种系列、适用请求，避免声称能处理所有生图任务。 |
| 固定视觉配方 | 具体风格、构图、色光、材质、比例与文字策略；注明来源和重建的不确定性。 |
| 变量定义 | 变量含义、必填项、可选项默认值；无需用户记住历史上下文。 |
| 完整提示词模板 | 只将确认的可变内容替换成命名占位符，例如 `{{subject}}`；其余描述写全。生成前展开所有变量，不向工具提交未解析占位符。 |
| 模式与设置 | 文生图或参考图模式、已选渠道、已知模型及设置；工具参数与提示词分开，未知值不得伪造。 |
| 参考图约定 | 所需文件的相对路径、各图用途、保留和修改范围；纯文本模式无此依赖。 |
| 执行与交付 | 将下节的输入整理、工具核实、逐张确认、停止条件、状态记录及结果检查规则写入独立 skill，不能仅链接本文件。 |

若生成 `agents/openai.yaml`，提供与实际用途一致的中文显示名、25–64 字符的简述，以及包含 `$<实际技能名>` 的默认提示。在 Codex 中默认允许自动发现，除非用户明确要求仅显式调用；更新时保留无关策略与依赖字段。不声明不存在的工具依赖。其他 Agent 的安装、发现和调用方式按其实际约定适配，不假定它会读取该文件或支持 `$skill-name` 语法；工具连接仍需在目标环境核实。

### 参考图处理

只有后续确需将图片作为输入，且用户已明确采用参考图模式时，才保存所需图片。先检查素材，将实际可获取的文件放入新 skill 的 `assets/`；记录各图在风格、角色、产品或构图上的具体用途，使用相对于 skill 根目录的路径。执行时解析为当前目录下的真实路径，按所选工具的实际参考图接口传递。

不为装饰、存档或重复展示复制图片。素材无法获取或当前工具不允许导出时，说明缺失并停止承诺该参考模式可用；请用户提供可保存素材，或明确接受改为纯文本配方。未解决前不交付声称可执行的缺图 skill，不以临时 URL、原会话“上一张”或虚构路径代替素材。

## 3. 独立 skill 的逐张批量流程

以下规则必须随配方一同写入新 skill；保存本身不授权任何生图调用。按配方决定是否在方案前单独选择背景，之后依次进行提示词及设置、单张确认、渠道选择：

1. **整理输入和背景。** 接收单项、列表或表格，明确总项数。配方要求单独选择背景时，按该配方在方案前交互选择并确认背景；否则将用户指定的背景带入方案，未指定时根据任务和配方设计，仅在关键要求不明确时补问。图片编辑要求保留原背景时不得擅自更换。用户已给出的内容带入供确认，不要求重新填写。缺少产品参考图或其他必填输入时只补问实际缺项。
2. **选择提示词及设置。** 沿用已保存方向与写法，不要求重新选模型写法或三个方案。交互展示完整展开提示词、比例、总图片数与用户已提供的设置；每行默认一张，用户要求多张时展开成分别确认的单张任务。保持文字边界：默认无字，需要文字时用已确认的准确内容。变量不得覆盖固定配方，与固定项冲突时展示差异。用户只要提示词时交付展开文本并停止，不进入生图确认和渠道选择。
3. **逐张确认。** 可先只读核实实际工具能力，但不得提前询问渠道。展示当前项编号、批次进度、完整提示词、背景、写法、模式、比例、文字策略、必要参考图及用途和“数量 1”，交互等待用户选择“确认生成”“先修改”“跳过此项”或“结束批次”；控件容量不足时保留确认和修改，并允许文字或自由输入跳过／结束。未回复、评价、取消或提出修改时不调用；修改后展示更新后的方案重新确认。
4. **选择渠道并生成。** 用户确认当前单张后，交互询问“原生生图”和“magpie-image MCP”，说明实际可用性与必要限制；控件不可用时用中文文字提问。以前或提前指定的渠道、预选和超时不算本次答复。选择可用且支持已确认方案的渠道后按实际接口直接调用一次、数量 1，不再重复确认；缺少能力时暂停，让用户选可用渠道或停止，不静默切换。若需实质修改提示词、比例、参考图或数量，展示新方案并重新确认单张、再选择渠道。方案及适用的背景设置、比例和总数在开批时确定，下一张、新图、续改或重试重新确认单张、再选择渠道；确认总数、“全部生成”或保存配方不能代替逐张确认与渠道选择。
5. **检查与交付。** 只交付真实返回的产物，检查固定视觉项、变量内容、参考图及文字偏差；偏差如实说明，不自动修图或重试。可保存时用户指定位置优先，否则使用当前工作区 `outputs/生图/YYYY-MM-DD_主题/主题_序号_v版本号.实际扩展名`；不同图片递增序号，同一图片续改递增版本，清理非法字符且不覆盖已有文件。不能保存时说明真实可用的位置或标识。
6. **记录与恢复。** 在当前对话记录项编号、变量值、待确认／完成／失败／结果待核实状态及真实产物位置。失败后暂停；超时或结果不明先只读核实，不自动重试。恢复时跳过完成项；仍不能确定结果时告知可能消耗额度，重新确认当前单张后再选择渠道。新会话缺少记录时请用户提供，不推测完成情况。

## 4. 校验与交付

校验新 skill 的 frontmatter、命名及相对引用；仅在存在 `agents/openai.yaml` 时校验其 UI 元数据，缺少该文件不视为 skill 不完整。若当前环境有 skill-creator 的 `quick_validate.py`，运行它，但不把该工具当成独立 skill 的运行依赖。无校验器时说明采用人工结构检查及其限制。

以一个新的变量值检查模板能否完整展开，以及脱离原对话和导演技能、忽略可选 `openai.yaml` 后是否仍有完整的配方、素材和执行规则。该检查仅做文本与文件检查，不调用生图工具。交付实际目录、目标 Agent 下的调用方式、变量用法和已知限制，不声称已经验证视觉复现效果。
